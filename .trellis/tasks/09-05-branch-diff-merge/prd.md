# PRD: 分支剧情树深度差异化分析与一键跨分支合并 (Branch Cherry-Pick/Merge)

## 1. 背景与用户痛点
在进行多分支跑团与复杂长篇剧情推演时，玩家常会在不同分支尝试不同的对话选择（例如分支 A 达成了特定线索触发，而分支 B 经历了精彩的战斗）。当前 Timelines 仅支持基础的分支分叉点只读对比，缺少深度分析与剧情内容互相移植能力：
1. 缺少逐轮对齐分析：无法快速识别两分支在同一轮次的情绪或走向分歧；
2. 跨分支移植成本极高：若玩家想把分支 B 中某一段极佳的 AI 回复或用户行动引入当前分支，只能手动复制粘贴，且容易丢失原楼层上下文与元数据；
3. 无法无损合并分支：缺乏基于公共祖先节点（LCA）将两条分支剧情“融汇为新会话”的安全能力。

## 2. 核心目标
1. **严格契合酒馆原生消息规范**：所有移植和合并均采用酒馆原生聊天消息对象结构与 `saveChatDebounced` / `openCharacterChat`，严禁私有数据格式，严禁损坏会话 line 0 的 JSONL 元数据。
2. **深度差异化对比面板升级**：
   - 逐轮对齐比对（Turn-by-turn Alignment）；
   - 展示关键差异统计（独有轮次、发言人占比、Swipe 分布）；
3. **精准单消息采摘移植 (Cherry-Pick Message)**：
   - 在 Diff 消息卡片上一键点击「🍒 采摘至当前会话」；
   - 纯净拷贝消息体（保留 `mes`, `name`, `is_user`, `send_date`, `extra` 等原生字段），无缝追加到当前活动会话尾部或指定位置；
4. **安全分支合并与新会话派生 (Fork & Merge to New Chat)**：
   - 提供「🔀 基于分叉点合并并生成新会话」选项；
   - 自动生成唯一规范文件名（如 `Branch_Merge_YYYY-MM-DD_HHmmss.jsonl`），以 LCA 公共前缀为基底，按需合并两分支剧情，并自动载入新会话。

## 3. 验收标准
- [ ] 单元测试套件覆盖核心合并与采摘逻辑，且保持 100% 通过（新增 `tests/merge.test.mjs`）；
- [ ] 在 Luker 实机环境打开 Diff 面板，执行单消息 Cherry-Pick，当前聊天无损新增并持久化；
- [ ] 执行多分支合并，成功派生新会话并自动切换，会话消息完整、时间线拓扑正常展开；
- [ ] 界面友好响应，错误情况防呆降级。
