# 多树视图（跨角色/群组同屏）设计

## Goal

为「跨角色/群组同屏渲染多棵时间树」的大特性产出 design.md 设计文档，供用户裁定是否立项实施。
本任务**只交付设计文档**，不写产品代码——设计经用户评审通过后，实施另立任务。

## Requirements

- R1 设计必须基于现有单树管线的真实架构事实（取证见 design.md §1，含 file:line 证据），不得凭空假设。
- R2 必须给出：数据聚合方案（多角色会话数据怎么取）、节点 id 隔离方案（现有 `message${counter}` 全局计数器在多树下必冲突）、布局拼装策略、渲染容器取舍、性能预算（L1-MF-11 硬约束下同屏树数与节点数上限）。
- R3 必须明确与现有能力的边界：单树路径零回归；语义索引 namespace（`char_*/group_*`）天然按角色隔离不受影响；A3 全局检索 / D1 全库聚合等跨角色先例的复用点。
- R4 必须列出**留给用户裁定的决策点**（数据面选树来源、布局拼装方式等），每项带推荐与理由。
- R5 纯函数模块（树集合聚合、多树拼装、id 命名空间化）必须设计为可在 Node.js 100% 单测的形态（L1-MF-11）。

## Acceptance Criteria

- [ ] design.md 存在且自包含（内联关键代码证据与 file:line，不引用任务目录外的悬空路径）。
- [ ] design.md 覆盖 R2 全部五项方案，每项含至少一个备选与取舍理由。
- [ ] design.md 末尾有「用户决策点」清单（≥3 项，各带推荐）。
- [ ] design.md 有验收基线：单树 E2E 10/10 与单测 147/147 零回归 + 多树新增纯函数模块的单测计划。
- [ ] 用户已阅读并裁定：纳入实施 / 修改后再审 / 不纳入。
